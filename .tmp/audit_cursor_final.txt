**1. You’re running parallel visual eras on purpose—but the player silhouette is still on the old spine**

Until those converge, reviewers will perceive a **hero vs world** mismatch in overworlds that already use revamped region cards and portals.

**2. Prologue procedural layer vs design-system palette discipline**

Docs (`CLAUDE.md`) reserve cyan for interactive accent. `RegionBackdrop`’s prologue build still paints stars and grid cues with **non–GameBoy** hex hues (`0x22d3ee`, `0xa78bfa`). That reads “premium sci‑fi UI ambient” layered on top of a Game Boy–rooted HUD—defensible if the prologue is *supposed* to feel alien, but it’s **the one backdrop path that escapes the restrained token set** unlike later regions where motion sticks to wheat dust / leaf blocks.

**3. Puzzle asset pipeline versioning is uneven—and that reads on screen**

`VISUAL_REVAMP_IMAGE_ASSETS` mixes many `*_backdrop_v1` puzzle arts with selective `*_v2`/`_v3` on regions and a few puzzles. Codewise that’s neutral; visually it often means **lighting sharpness and ground-plane treatment won’t lock** region-to-region until the long tail catches up.

**4. Narration vs implementation drift in comments**

The JSDoc on `getRegionBackdrop()` still describes skipping static backdrops when a region procedural is chosen. The implementation **always** composites static + optional `RegionBackdrop`. That’s harmless at runtime but it’s exactly the sort of stale API story that slows the next engineer’s mental model—and “second‑opinion cohesion” absolutely includes docs matching behavior.

- **Architecturally**, the refactor toward **fullscreen handcrafted BG + light motion + themed chrome** is coherent and avoids the classic indie trap of “beautiful art under a distracting vector parallax.”

The first is the sharper discontinuity today; the second is backlog polish that will unify perceived quality.

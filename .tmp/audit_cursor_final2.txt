## Where cohesion is still strained (honest critique)

### 1. Multiple art “eras” living side by side  
You still have **`assets/prologue`**, **`prologue_rework`**, **`prologue_sheets`**, **`visual_revamp`** in the manifest story. That is defensible historically, but experientially it’s the main place subtle **character scale, outline weight, saturation, or dither style** can disagree between Professor Node overhaul sheets and `VISUAL_REVAMP` portraits in the puzzle shell—not a coding bug, a **creative-direction merge** problem the code faithfully reflects.

### 2. Two palette philosophies in one product  
Documentation in `CLAUDE.md` stresses a **Game Boy–like** lexical set (`COLORS.SUCCESS`, `FRAME_BG`, sparing `CYAN_GLOW` for interactivity). The **prologue / cosmic** lane legitimately bends that with purples and sky cyans baked into themes and procedural layers:

### 3. Token drift in UI components (`LessonCard`)  
The parchment palette **re-hardcodes** many of the same numbers as `COLORS` / `COLOR_HEX` instead of importing shared tokens (`0xe0f8d0`, `#06b6d4`, etc.). That duplicates the “semantic gold slot uses cyan” kind of ambiguity:

### 4. `CYAN_GLOW` semantics vs widespread accent use  
Studio rule: cyan = **interactive**. In practice cyan also appears as **decorative accent** on frames, lesson cards, and `RegionBackdrop` grid lines (`RegionBackdrop.ts` hex grid uses `COLORS.CYAN_GLOW`). Again, either **relax the rule in docs** (“cyan signals tech / Algorithmia vibe, not only click targets”) or reserve a second token (`ACCENT_TECH`) so QA and future you can lint intent.

### 5. Narrative backdrop parameter that does not yet change the painting  
Twin Rivers retains `mode: 'dual' | 'converged'` but the static image path is commented as **the same for both**; only leaves/mist behavior differs. Players who notice story beats (“rivers merge”) might expect the **plate** to change, not only particle choreography—currently a **thematic cohesion gap**, not a performance one.

## Code architecture verdict

- **Strength:** Clear layering (static keyed art → optional motion → shared UI frame → puzzle-specific sprites) matches how pixel games should composite; comments document *why*, which aids art passes and onboarding devs.
- **Watch:** Growing **conditional preload** chains per scene multiply the chances of “works on my machine” if a key slips; tests help for manifest paths but not every texture existence at runtime.
- **Visual-product alignment:** Art direction is trending **production-pixel backdrops + restrained VFX**, which matches the codebase comments—keep pushing **one hero painting per screen** rather than stacking full illustrations.
